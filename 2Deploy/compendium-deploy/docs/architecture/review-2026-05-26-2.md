## 1 · Make the render seam the single presentation surface — Strong

**Files:** `compendium/cli/render.py` · `tui/screens/{dashboard,workbench,sources,pages,curation}.py`

**Problem.** Shipping the CLI render seam (review #1) left its mirror: the six TUI screens
re-formatted the same scalars (coverage `:.3f`, the `YYYY-MM-DD HH:MM` timestamp, the fallback
flag, payload truncation) in their `_populate` methods. Change a format → touch render plus six
screens.

**Solution (PR #22).** Extract `fmt_coverage` / `fmt_ts` / `fmt_fallback` / `fmt_fallback_suffix`
/ `fmt_payload` into the render module; route render's own renderers through them and have the
screens consume them. One format, one home.

## 2 · One `StoreProjector` seam for entity → derived store — Worth exploring

**Files:** `index/sync.py` · `index/documents.py` · `index/projectors.py` (new) · `graph/projection.py`

**Problem.** The entity→store mapping-and-write was split across `documents.py` (OpenSearch/Qdrant
shapes), `graph/projection.py` (Memgraph nodes/edges), and a per-`index_kind` branch inside
`sync._write_one`.

**Solution (PR #25), scoped.** A `StoreProjector` adapter per store with a `PROJECTORS` registry;
`_write_one` collapses to one lookup.

> **Scope correction.** The review's premise "Memgraph isn't on the sync queue" was imprecise:
> incremental writes already enqueue and recover the `memgraph` kind. Only the full-*rebuild* path
> stays off-queue, and the `SYNTHESIZES`-on-rebuild wipe is orthogonal. Both were **left as-is**;
> PR #25 is just the dispatch/mapping seam — the durable locality win.

## 3 · The curation lifecycle as one deep operation — Worth exploring

**Files:** `curate/lifecycle.py` (new) · `curate/synth.py` · `trace/promote.py` · (removed) `curate/promote_hook.py`

**Problem.** The signal state machine (`open → in_progress → addressed`) and the synth/promote
ordering lived in callers — a status flip in `synth.py`, a separate `promote_hook.py` reached by
an inline import inside `promote()`, with the stuck-`in_progress` failure mode invisible.

**Solution (PR #24).** `curate/lifecycle.py` owns the transitions: `begin` (`open → in_progress`)
and `address_on_promote` (`in_progress → addressed` + `SYNTHESIZES` edges). Both stay
curator-triggered (ADR-009: no autonomous promotion) — locality deepened, not automation.

---

## 4 · Collapse the TUI load cycle into a `DataScreen` helper — Worth exploring

**Files:** `tui/screens/base.py` (new) · the six screens

**Problem.** The `@work(thread=True)` → try/except → two `call_from_thread` hops cycle was copied
across ten screen workers.

**Solution (PR #23).** A `DataScreen.run_threaded(fn, *, on_ok, on_error=, error_label=)` base
method owns the marshal-back cycle; each worker is its `@work` declaration plus one call. The
`@work` decorators (the worker declarations) are unchanged, so threading semantics are preserved.

---

## 5 · Smaller cleanups — Speculative

**Files:** `graph/client.py` + nine call sites

**Problem.** The Memgraph Bolt driver was opened with `graph_driver()` and closed by hand at nine
short-lived call sites.

**Solution (PR #26), trimmed.** Add `graph_connection()`, a context manager mirroring
`db.connection.connection()`, used everywhere the driver is short-lived; the one long-lived holder
(`sync._Stores`) stays on `graph_driver()`. The other candidate-5 items (the `all_*_ids` dedup,
the `parse_markdown` name collision) were **left alone** — not worth the churn / ripple.
