## Why

PostgreSQL is the operational system of record for Compendium (ADR-004): every source, chunk, wiki page, revision, query trace, and curation signal lives there, and the OpenSearch/Qdrant/Memgraph indexes derive from it. Phase 1 delivers that backbone — the full operational schema as ordered Alembic migrations and a synchronous access layer — so Phases 2 and onward have somewhere to read from and write to. It depends on the Phase 0 skeleton (`phase-0-project-skeleton`).

## What Changes

- Alembic initialized against `POSTGRES_URL`, configured for hand-written (non-autogenerated) sync migrations.
- The full operational PostgreSQL schema as hand-written Alembic migrations in the documented 10-step order: enums; `sources`/`source_documents`; `corpus_revisions`; `chunks`; `wiki_pages`/`wiki_pages_topics`; `wiki_page_revisions` (with the deferred circular `current_revision_id` FK); `index_sync_state`; `promotion_events`; `query_traces`; `graph_curation_signals`/`graph_analysis_runs`.
- The four read-only TUI views: `v_sync_lag`, `v_failed_sources`, `v_recent_traces`, `v_open_curation_signals`.
- A thin `compendium/db/` repository module wrapping `psycopg 3` (sync) for connection management and raw-SQL queries — no ORM.
- Deviation from `docs/Compendium.md`, deliberately scoped here: `query_traces.query_embedding` is `REAL[]` rather than `VECTOR(1024)`; pgvector is **not** installed in v0.1 (sanctioned by the doc's stated fallback — vector search lives in Qdrant, not Postgres).
