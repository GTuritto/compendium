## ADDED Requirements

### Requirement: Schema migrations apply and reverse cleanly

The operational PostgreSQL schema SHALL be expressed as hand-written Alembic migrations applied in the documented dependency order. `alembic upgrade head` from an empty database SHALL produce the full schema, and `alembic downgrade base` SHALL reverse it completely.

#### Scenario: Upgrade builds the full schema

- **WHEN** `alembic upgrade head` runs against an empty database
- **THEN** all operational tables, enums, and views are created without error

#### Scenario: Downgrade reverses cleanly

- **WHEN** `alembic downgrade base` runs against the fully migrated database
- **THEN** every table, enum, and view created by the migrations is dropped, leaving an empty schema

#### Scenario: Migrations are not autogenerated

- **WHEN** a migration file is inspected
- **THEN** its DDL is hand-written (e.g. via `op.execute`) and ordered per the documented 10-step sequence

### Requirement: Operational schema completeness

The schema SHALL contain the operational tables `sources`, `source_documents`, `corpus_revisions`, `chunks`, `wiki_pages`, `wiki_pages_topics`, `wiki_page_revisions`, `index_sync_state`, `promotion_events`, `query_traces`, `graph_curation_signals`, and `graph_analysis_runs`, with the documented enum types, foreign keys, indexes, and constraints.

#### Scenario: Circular foreign key resolved

- **WHEN** the migrations creating `wiki_pages` and `wiki_page_revisions` are applied
- **THEN** `wiki_pages.current_revision_id` references `wiki_page_revisions(id)` via a constraint added after both tables exist, and the upgrade succeeds

#### Scenario: Query embedding stored without pgvector

- **WHEN** the `query_traces` table is created
- **THEN** its `query_embedding` column has type `REAL[]` and is nullable, and no `vector` extension is required

#### Scenario: Native enum types exist

- **WHEN** the schema is inspected after upgrade
- **THEN** the enum types `source_kind`, `page_kind`, `page_status`, `page_generator`, `inspection_status`, `index_kind`, `sync_state`, `promotion_kind`, `curation_signal_kind`, and `curation_signal_status` exist as native PostgreSQL `ENUM` types

### Requirement: Operational views

The schema SHALL provide the read-only views `v_sync_lag`, `v_failed_sources`, `v_recent_traces`, and `v_open_curation_signals` for the TUI to consume.

#### Scenario: Views are queryable after upgrade

- **WHEN** any of the four operational views is selected from after `alembic upgrade head`
- **THEN** the query succeeds and returns the documented columns

### Requirement: Database access layer

The system SHALL provide a `compendium/db/` module that manages synchronous `psycopg 3` connections and executes queries with raw SQL. No ORM SHALL be used.

#### Scenario: Round-trip insert and read

- **WHEN** a stub `source` row and a stub `wiki_page` row are inserted through the access layer and then read back
- **THEN** the returned rows match what was inserted, including JSONB, array, and enum-typed columns
