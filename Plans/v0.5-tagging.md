## Goal

Add curator-assigned, retrieval-filter-grade tags on sources and wiki pages, so
the corpus can be organized by lightweight orthogonal labels and queries/asks
can be scoped to a tag, without reinventing topics.

## Why this plan exists

It locks in that tags are orthogonal to topics and aliases, that they are
system-of-record in PostgreSQL and propagated into the derived indexes for
index-level filtering, and that the filter is recorded in the trace. Without it,
tagging risks collapsing into the topic model or becoming a display-only
attribute that cannot scope retrieval.

   columns on `sources` and `wiki_pages` — decided per the open question).
2. Tags repository: add/remove/list tags; attach/detach to a source/page.

### Nb — index propagation

**Purpose:** index-level filtering, not post-hoc.

**Tasks:**

1. Add a tag field to the OpenSearch mapping and the Qdrant payload.
2. `reindex` / sync writes tags for each source/page; mapping + payload tests.

**Files modified:** `compendium/index/opensearch.py`, `compendium/index/qdrant.py`, sync.

**Decision flagged:** tag inheritance — a source tag flows to its chunks/source page (open question 3).

### Nc — retrieval filter

**Purpose:** scope retrieval by tag.

**Tasks:**

**Files modified:** `compendium/retrieve/pipeline.py`, `compendium/retrieve/search.py`

**Decision flagged:** AND vs OR semantics for multiple tags (open question 2).

## Testing plan

| # | Layer | Scenario | Verify |

| 1 | integration | tag/untag a source and a page | attachments persist; no topic/alias/edge side effects |

## Out of scope (do NOT build)

- Agent-assigned tagging via the access surface (agent-write; backlog item 1).
- Controlled-vocabulary enforcement (free-form first; revisit if needed).
- Tag-scoped admin ops (delete/reindex by tag) — backlog admin item.

## Open questions to confirm before starting

1. Join tables vs `text[]` columns. Recommendation: join tables (clean rename/
   merge, usage counts), accept the extra joins.
2. Multiple-tag filter: AND vs OR. Recommendation: OR by default with an
   AND option, mirroring common tag UIs.
3. Tag inheritance: does a source tag apply to its chunks/source page for
   filtering? Recommendation: yes — a source tag covers its derived content.
