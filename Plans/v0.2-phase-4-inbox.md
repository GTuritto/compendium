## Goal

Drop-and-forget ingestion via a watched inbox directory.

## Why this plan exists

v0.1's ingestion contract requires the curator to open a terminal
every time. For a personal knowledge tool that the curator interacts
with several times a day — clipping web articles, saving PDFs from a
paper reader, dropping notes — the friction shows up. Files sit in
Downloads waiting for the curator to remember to ingest them; some
never make it.

Phase 4 ships the smallest mechanism that satisfies "drop and
forget": a `~/Compendium/inbox/<kind>/` directory layout watched by
an OS-native path-unit. Files dropped under any `<kind>/` subdir
auto-ingest with that kind, get indexed, and move to
`inbox/processed/<YYYY-MM-DD>/` on success or
`inbox/failed/<YYYY-MM-DD>/` (with a `<file>.error` sidecar) on
parse failure. `compendium inbox install` creates the layout and
installs the watcher; `compendium inbox uninstall` removes the
watcher (preserving the directory and its contents);
`compendium inbox status` reports recent counts;
`compendium inbox process` is the worker the watcher invokes (and
the operator's manual catch-up command).

The plan locks five decisions:

1. **Parent directory is the kind.** No metadata sidecar, no content
   sniffing. The curator's choice of which `<kind>/` to drop into
   is the ingestion kind.
2. **Atomic moves, no locks.** `Path.rename()` is atomic on a single
   filesystem. Concurrent watcher fires resolve by losing the race
   on a `FileNotFoundError`; no advisory locks, no coordination
   state.
3. **Two failure classes, two routes.** Parse failures move to
   `failed/<date>/` with a sidecar — they will not auto-retry.
   Systemic failures (Postgres unreachable, etc.) leave the file in
   place — the next watcher fire retries.
4. **No long-running Python watcher.** The OS path-unit is the
   watcher; Python only runs during the per-fire CLI invocation.
   Per ADR-012, in-process file watching is the access-surface
   daemon's job (Phase 7+).
5. **Skip in-flight downloads.** Dot-files and the standard
   `.tmp` / `.part` / `.crdownload` / `.download` suffixes are
   skipped. Operators drop completed files; the rules cover the
   common download-tool conventions.

## Sub-phases

### 4a — `compendium inbox install` / `uninstall` + config

**Purpose:** ship the install + uninstall half — create the
directory layout, write the OS-native watcher unit, register it,
remove it idempotently. No file processing yet.

**Tasks:**

1. `compendium/config.py`: add `Config.inbox_path: str` populated
   from `config/settings.yaml` `inbox.path`.
2. `config/settings.yaml`: new `inbox:` section sourcing
   `${INBOX_PATH:-~/Compendium/inbox}`.
3. `.env.example`: add `INBOX_PATH=~/Compendium/inbox` with a
   comment block explaining the directory contract.
4. `compendium/inbox/__init__.py`: module surface re-exporting the
   public helpers (`create_layout`, `install_watcher`,
   `uninstall_watcher`, `InboxError`).
5. `compendium/inbox/install.py`:
   - `create_layout(path: Path) -> None` — idempotent `mkdir -p` of
     the seven subdirectories (`book`, `article`, `paper`, `note`,
     `web`, `processed`, `failed`).
   - macOS branch: write
     `~/Library/LaunchAgents/com.compendium.inbox.plist` with
     `WatchPaths` listing each `<kind>/` subdir and
     `ProgramArguments` invoking
     `uv run --project <repo> python -m compendium inbox process --path <inbox>`.
     Load via `launchctl bootstrap gui/<uid>`.
   - Linux branch: write
     `~/.config/systemd/user/compendium-inbox.{path,service}`. The
     `.path` unit carries five `PathChanged=` lines (one per kind).
     The `.service` invokes the uv-driven process command. Enable
     via `systemctl --user enable --now compendium-inbox.path`.
6. `compendium inbox install [--path <dir>]` CLI verb. Defaults
   `--path` to the configured `inbox_path`. Creates the layout +
   installs the watcher. Prints the resolved path + loader exit.
7. `compendium inbox uninstall` CLI verb. Unloads + removes the
   watcher unit; idempotent. Does NOT delete the inbox directory
   or any files.
8. Unit tests for cadence-style checks: layout shape, plist
   `WatchPaths` content, systemd path-unit `PathChanged=` lines,
   non-darwin/linux refusal.

**Files added:** `compendium/inbox/__init__.py`,
`compendium/inbox/install.py`
**Files modified:** `compendium/__main__.py` (inbox subparser +
`_inbox` handler), `compendium/config.py`, `config/settings.yaml`,
`.env.example`

**Decision flagged:** the install module duplicates a handful of
helpers from `compendium/schedule/install.py` and
`compendium/backup/schedule.py` (LaunchAgent skeletons, systemd unit
skeletons). Three callers is the trigger for a v0.3 refactor into
`compendium/_oslaunch/`; in v0.2 Phase 4 the duplication stays.

### 4b — `compendium inbox process` (the worker)

**Purpose:** the body of the watcher's invocation — scan the inbox,
ingest each file, route to `processed/<date>/` or `failed/<date>/`.

**Tasks:**

1. `compendium/inbox/process.py`:
   - `process_inbox(path: Path) -> ProcessReport` — scans each
     `<kind>/` subdir; skips ineligible files; per file, calls
     `compendium.ingest.pipeline.ingest(file_path, kind=kind)`;
     routes by `status` (`ingested`/`unchanged` → `processed`,
     `failed` → `failed` + sidecar); on raised exception leaves
     the file in place and re-raises.
   - `ProcessReport` dataclass: `processed: list[Path]`,
     `failed: list[tuple[Path, str]]`, `skipped: list[Path]`,
     `errored: bool`.
   - After the per-file loop: if any file was processed or
     parse-failed, run one `compendium index sync` to drain the
     indexing queue.
2. Eligible-file filter: skip files whose name starts with `.` or
   ends in `.tmp` / `.part` / `.crdownload` / `.download`.
3. Atomic-move helper: `_route(file: Path, dest_dir: Path) ->
   bool`. Creates `dest_dir/<YYYY-MM-DD>/` (today, local time) and
   `Path.rename`s the file in. Returns `False` on
   `FileNotFoundError` (lost the race), `True` on success.
4. Failed-file sidecar: writes `<dest_dir>/<YYYY-MM-DD>/<file>.error`
   containing the `detail` string returned by ingest.
5. `compendium inbox process [--path <dir>]` CLI verb. Default
   path from config. Prints a summary block:
   `processed=N failed=M skipped=K`. Exits 0 on no-systemic-failure,
   non-zero otherwise.
6. Unit tests: kind classification; skip rule; rename-race lost;
   parse-failure routing + sidecar content; systemic-failure
   leaves the file in place; the post-loop index sync runs only
   when at least one file was routed.

**Files added:** `compendium/inbox/process.py`
**Files modified:** `compendium/__main__.py`,
`compendium/inbox/__init__.py` (re-exports), `tests/test_inbox.py`

**Decision flagged:** `process_inbox` is intentionally NOT async.
The watcher fires sequentially; ingest is CPU + IO bound and
existing `compendium.ingest.pipeline.ingest()` is synchronous; the
indexing queue drain is async internally but called synchronously
here. No `asyncio` surface at this layer.

### 4c — `compendium inbox status`

**Purpose:** one command that tells the curator what is waiting,
what processed recently, and what failed.

**Tasks:**

1. `compendium/inbox/status.py`:
   - `read_status(path: Path) -> InboxStatus` returns a snapshot
     with `path`, `watcher_loaded: bool`, per-kind waiting counts,
     processed_today / processed_yesterday counts, failed_today /
     failed_yesterday counts, most-recent-processed +
     most-recent-failed timestamps.
   - `watcher_loaded` delegates to
     `compendium/inbox/install.py`'s platform-specific helper
     (mirrors `compendium/schedule/status.py`'s pattern).
2. `compendium inbox status [--path <dir>] [--format text|json]`
   CLI verb. Exits 0 unconditionally (the inbox is usable even
   when the watcher is uninstalled; status is informational).
3. Unit tests: empty inbox returns all zeros + watcher_loaded
   False; populated inbox returns correct waiting / processed /
   failed counts; `to_dict()` is JSON-clean.

**Files added:** `compendium/inbox/status.py`
**Files modified:** `compendium/__main__.py`,
`compendium/inbox/__init__.py`, `tests/test_inbox.py`

**Decision flagged:** status reads the filesystem, not a database.
No inbox-state table is added. The filesystem is the source of
truth.

## Out of scope for Phase 4 (do NOT build)

- `--mine` provenance on drop (no `notes-mine/` subdir).
- URL ingestion via the inbox (no `.url` files).
- Sub-directory recursion under `<kind>/`.
- Retention / pruning of old `processed/` and `failed/` dirs.
- Notifications on success or failure.
- Auto-classification of kind by file content.
- In-process Python file-watching (`watchdog` library).
- TUI integration for the inbox.
- A `compendium inbox drain` synonym for `process`.
- A long-running daemon-side inbox handler (that's Phase 7+).

## Open questions — resolved at the review gate (2026-05-30)

1. **Default inbox path.** RESOLVED: `~/Compendium/inbox` (per
   build plan; outside the repo, operator data, not repo state).
2. **`compendium inbox status` exit code.** RESOLVED: always 0 —
   the inbox is usable manually even when the watcher is
   uninstalled; status is informational.
3. **systemd path-unit shape.** RESOLVED: one `.path` unit with
   five `PathChanged=` entries (systemd 245+); the older-systemd
   fallback is documented in the operational doc.
4. **Handling `status="unchanged"` from ingest.** RESOLVED: treat
   as success — move to `processed/<today>/`; the corpus is
   correct either way.
5. **Pre-create dated `processed/<today>/` and `failed/<today>/`
   on install?** RESOLVED: no; the process verb creates them on
   first need.
