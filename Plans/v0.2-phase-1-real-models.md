# v0.2 Phase 1 — Real-model validation: Implementation Plan

Date: 2026-05-30

OpenSpec change: `openspec/changes/v0.2-phase-1-real-models/`

## Goal

Confirm BGE-M3 (embeddings) and OpenRouter Claude Sonnet 4.5 (synthesis) work end-to-end
against the existing fixtures and golden suite with `COMPENDIUM_EMBED_STUB` and
`COMPENDIUM_SYNTH_STUB` both unset, and write down the per-host model strategy so future
v0.2 phases can assume the seams are trusted.

## Why this plan exists

v0.1 shipped two seams — `compendium/index/embedder.py` and `compendium/wiki/synth.py` —
behind stub/real toggles, and every test, every CI run, and every recorded smoke walk to
date has exercised the stubs. Before any v0.2 phase changes the surface area (retrieval
tuning, `ask`, the access surface, autonomous edge extraction), the real seams have to
be verified end-to-end at least once on the primary host, and the per-host model strategy
has to stop living in build-plan prose and become an operational document.

This plan locks in three decisions:

1. **Hermetic stays the default.** CI, the fast tier, and the golden tier continue to run
   with `COMPENDIUM_EMBED_STUB=1` and `COMPENDIUM_SYNTH_STUB=1`. The real-model walk is an
   opt-in tier (a new pytest `live` marker plus a manual smoke section), never on the push
   path. Reason: cost and reproducibility.
2. **Per-host strategy is config, not code.** Apple Silicon, Intel Mac, and Raspberry Pi
   all run the same code paths; only the four env vars (`SYNTHESIS_ENDPOINT`,
   `SYNTHESIS_MODEL`, `EMBEDDINGS_ENDPOINT`, `EMBED_MODEL`) differ. No host autodetection,
   no adapter switches. Reason: minimum surface area; the existing seams already abstract
   the difference.
3. **Phase exit is the primary host only.** Phase 1 records green evidence on the
   curator's primary host (Mac mini Apple Silicon). The other supported hosts get
   documented recipes and are validated on demand later. Reason: weekend-sized scope.

## Sub-phases

### 1a — `live` pytest marker + opt-in live test module

**Purpose:** give Phase 1 (and every later v0.2 phase) a hermetic-by-default way to
exercise the real seams from `uv run pytest`, with a clean skip when the env is not set
up for live calls.

**Tasks:**

1. Register a `live` marker in `pyproject.toml` alongside `golden` and `integration`,
   described as "tests that hit real model endpoints; opt-in, never in CI's default tier".
2. Add `tests/test_live_models.py` with two `@pytest.mark.live` tests:
   - `test_real_embedder_roundtrip` — instantiates `OpenAIEmbedder` via `get_embedder()`,
     embeds three short fixture strings, asserts: list-of-three vectors, each of length
     `EMBED_DIM` (1024), each unit-normalized within `1e-3`, and pairwise distinct.
   - `test_real_synthesizer_writes_prose` — instantiates `LLMSynthesizer` via
     `get_synthesizer()` with a tiny in-test chunk list and asserts the returned prose
     starts with an H1, is at least 200 characters, and does not contain the stub-only
     phrase "stub synthesizer".
3. Both tests skip (not fail) when:
   - `COMPENDIUM_EMBED_STUB` / `COMPENDIUM_SYNTH_STUB` is set, or
   - the corresponding endpoint is unreachable (a single `httpx.get` with a 2-second
     timeout, mirroring the existing skip-if-unreachable pattern in `tests/conftest.py`).
4. Wire the marker through `pyproject.toml`'s default `addopts` (or document the run
   command) so `uv run pytest` continues to exclude `live` by default; `uv run pytest -m
   live` runs only the live tests.

**Files added:** `tests/test_live_models.py`
**Files modified:** `pyproject.toml`

**Decision flagged:** `live` is opt-in, off by default, never in CI. Endpoint
unreachability is a skip, not a failure — matches the `integration` convention.

### 1b — Real-model smoke walk on the primary host

**Purpose:** run the cumulative manual smoke walk from `tests/manual/smoke_test.md` end
to end with both stubs unset, capture the outputs as evidence, and confirm the derived
indexes hold real vectors.

**Tasks:**

1. With `docker compose up -d` (Postgres, OpenSearch, Qdrant, Memgraph) and a clean
   vault, run the existing Phase 2 → Phase 9 smoke scenarios with `COMPENDIUM_EMBED_STUB`
   and `COMPENDIUM_SYNTH_STUB` both unset. Use the real `.env` values for OpenRouter and
   Docker Model Runner.
2. Capture, in a new `tests/manual/test-runs/v0.2-phase-1-real-models.md` evidence file:
   - host (name, chipset), date, the resolved values of the four model env vars;
   - per-scenario pass/fail and wall-clock seconds (one line per scenario);
   - a Qdrant spot-check: `qdrant-client` pulls one vector from the `chunks` collection,
     asserts shape 1024 and unit norm (proves the vectors are real, not stub);
   - one synth output diff: ingest `tests/fixtures/sample.pdf`, run `compendium synth
     concept "<seeded name>"`, paste the first 30 lines of the resulting page and confirm
     it is not the stub body.
3. Run `uv run pytest -m live` and record pass/fail + timing in the same evidence file.

**Files added:** `tests/manual/test-runs/v0.2-phase-1-real-models.md`
**Files modified:** none in `compendium/` (no code changes in this sub-phase)

**Decision flagged:** the evidence file is the artifact future phases point at when they
need to claim "real models are known to work on the primary host". It lives under
`tests/manual/test-runs/` alongside existing run logs.

## Out of scope for Phase 1 (do NOT build)

- A model-strategy autodetector. The strategy lives in env vars; no host-introspection
  code lands.
- An embedding or synthesis cache, batch-tuning, or token budgeter (Phase 5 / Phase 6).
- A DMR install/uninstall wrapper. Standing DMR up on a host stays a manual step
  documented in `docs/operations/real-models.md`.
- A new model adapter or alternate endpoint client. The existing OpenAI-compatible
  client covers both DMR and OpenRouter.
- Validating Intel and Pi hosts as part of phase exit; their rows in the strategy doc
  are documented but not green-lit until run separately.
- Any change to retrieval ranking, synthesis prompts, or chunk shape — this is a
  validation phase, not a tuning phase.

## Open questions — resolved at the review gate (2026-05-30)

1. **Embeddings on Intel/Pi hosts.** RESOLVED: option (a) — DMR running BGE-M3 on CPU at
   reduced batch. Keeps the "local-first" posture intact; the strategy doc records the
   throughput penalty next to the row.
2. **`live` exclusion mechanism.** RESOLVED: add `addopts = "-m 'not live'"` under
   `[tool.pytest.ini_options]` in `pyproject.toml` so default `uv run pytest` excludes
   live tests; `uv run pytest -m live` overrides. The README and operations doc point
   this out.
3. **Evidence file format.** RESOLVED: free-form Markdown under
   `tests/manual/test-runs/`, mirroring the existing run logs there. Human-read, not
   machine-parsed.
