# v0.4 Phase 1 — The Single-Point A/B: Implementation Plan

Date: 2026-06-12
Branch: `v0.4-phase-1-single-point-ab` (off `main`)
OpenSpec change: `openspec/changes/v0.4-phase-1-single-point-ab/`
Spec source: [docs/COMPENDIUM_V0.4_BUILD.md](../docs/COMPENDIUM_V0.4_BUILD.md) § 5; § 8 (pre-registration).

## Goal

Produce the first result that means something: on the real corpus, today, do
curated pages beat raw chunks. Build the chunk-only control arm (ADR-016),
harvest the frozen probe set from real `ask_traces`, and run both arms
against the identical corpus state, reporting per-query page-minus-chunk
deltas that the pre-registered criteria are read against.

## Why this plan exists

The control arm is the load-bearing instrument of v0.4; this plan locks the
measurement methodology before any number is produced, so the verdict cannot
be quietly shaped after the fact. Three decisions are pre-registered here
(not discovered during analysis): the scoring unit, the normalization
treatment, and determinism via exact search. It also fences the control arm
as a validation pathway, not a fifth surface.

## Verified ground

- The chunk machinery exists end-to-end behind the coverage gate:
  `retrieve/pipeline.py:204-213` (chunk fan-out + fusion + citations),
  `search.opensearch_chunks` / `search.qdrant_chunks`. The control arm is a
  flag and a return-shape choice, as § 5 assumed. The stop-and-reassess
  clause does not trigger.
- Query normalization expands aliases sourced from `wiki_pages.aliases`
  (`pipeline.py:143`); the OpenSearch synonym filter is likewise
  alias-derived. The wiki therefore leaks into any arm that shares the
  normalized query — handled by pre-registration (decision 2 below).
- Qdrant supports per-request exact kNN (`SearchParams(exact=True)`); the
  HNSW flap documented in v0.2 Phase 5 disappears for measurement runs.
- `ask_traces` (migration `0012`) holds every real question asked, joined to
  retrieval traces — the harvest source.

## Pre-registered measurement decisions (ADR-016 carries these)

1. **Scoring unit: the page.** Both arms are scored in page space; a chunk
   hit credits its parent source page. Bias direction: flatters the chunk
   arm slightly (any chunk from the right source counts). A surviving
   positive page-arm delta is therefore conservative.
2. **Normalization applies to both arms.** Alias curation is part of what
   the wiki is; the contamination strengthens the control, so a positive
   delta survives it. A null must be read knowing the control freeloaded.
3. **Exact search for measurement.** Both arms use Qdrant `exact=True` in
   `validate run` only; production retrieval keeps HNSW.

## Sub-phases

### 1a — the chunk-only control arm (ships ADR-016)

**Purpose:** the instrument: identical fan-out, no page layer, fenced.

**Tasks:**

1. `arm: str = "pages"` parameter on `retrieve/pipeline.run()`/`query()`:
   `"chunks"` runs the chunk fan-out unconditionally, produces no page
   ranking, sets `fallback_to_chunks=True`-style citation output, and stamps
   `pipeline.arm` in the trace payload. Default path byte-identical.
2. Thread optional exact-search params through `retrieve/search.py`
   (`SearchParams(exact=True)` when the caller asks; default unchanged).
3. ADR-016 inline in `docs/Compendium.md`: the control arm, its fencing
   (validate-only), and the three pre-registered decisions.
4. Prove the supported surfaces unchanged: full fast tier + Phase 0
   wire-format snapshots green with no edits.

**Files modified:** `compendium/retrieve/pipeline.py`,
`compendium/retrieve/search.py`, `docs/Compendium.md`.
**Decision flagged:** no facade/`query` exposure — the arm is reachable only
from `compendium/validate/` (deletion test: remove validate/, and the arm
has zero callers).

### 1b — probe set harvest

**Purpose:** turn real questions into the durable, frozen instrument.

**Tasks:**

1. `compendium/validate/probes.py`: harvest distinct questions from
   `ask_traces` (joined to their retrieval traces for context); emit
   curation candidates as YAML.
2. Probe-set format: golden-style slug-keyed entries — `query`, `expected`
   (relevant page slugs), optional `notes`; a `frozen: true` header the
   runner refuses to run without.
3. `compendium validate harvest [--out DIR]` (default
   `~/.compendium/probes/`): writes `candidates-<date>.yaml`; the curator
   prunes/labels and freezes as `probe-set.yaml`. Nothing lands in the repo.
4. Canned fixture probe set under `tests/fixtures/` (synthetic queries over
   the existing fixture corpus) for the hermetic tier.

**Files added:** `compendium/validate/__init__.py`,
`compendium/validate/probes.py`, `tests/fixtures/probe-set.yaml`.
**Decision flagged:** probes live outside the repo by default — real
personal queries must not ship in `tests/` or the 2Deploy bundle.

### 1c — the A/B runner and report

**Purpose:** both arms, same data, one honest table.

**Tasks:**

1. `compendium/validate/run.py`: for each probe, run the pipeline twice in
   one process (`arm="pages"`, `arm="chunks"`), exact search on both;
   compute per-probe page-space metrics (hit@K, recall@K, MRR against
   `expected`) reusing `tests/golden/__init__.py::compute_metrics` shapes
   where they fit (lift into `compendium/validate/metrics.py` if the import
   direction demands it).
2. Report: per-query table (probe, page-arm metrics, chunk-arm metrics,
   delta) + aggregate row, prefixed by the methodology header (the three
   pre-registered decisions); `--format json` writes the artifact next to
   the probe set (`report-<date>.json`).
3. `compendium validate run --probes <file>` wired in `__main__.py`
   (one tail call); traces persist for both arms (every query writes a
   trace — the constitution holds for measurement too).

**Files added:** `compendium/validate/run.py`,
`compendium/validate/metrics.py`, `tests/test_validate.py`.
**Files modified:** `compendium/__main__.py`, `compendium/cli/render.py`.
**Decision flagged:** snapshot freezing stays operational (run `compendium
backup` before a measurement run — the audit artifact), not a runner
feature; the runner asserts nothing about backups.

### 1d — docs and close

**Tasks:** `docs/operations/validation.md` (harvest → curate → freeze →
backup → run → read against the pre-registration); CHANGELOG; smoke section
appended to `tests/manual/smoke_test.md`; full fast + golden green;
`./release.sh 0.3.2` in the completion commit.

## Acceptance tests (QA plan)

Priorities: P0 = blocks the phase, P1 = blocks ready-for-review, P2 = nice.

### TC-AB-001 — control arm returns ranked chunks (P0, pipeline)
**Preconditions:** dev stack up, fixtures ingested + reindexed (the smoke
walk state); stub embedder.
**Steps:** run the pipeline with `arm="chunks"` for "psychological safety".
**Expected:** non-empty ranked chunks with parent-source attribution; no
page ranking in the result; trace persisted with `pipeline.arm="chunks"`.

### TC-AB-002 — supported surfaces byte-identical (P0, regression)
**Steps:** full fast tier + Phase 0 wire-format snapshots, zero edits.
**Expected:** green. Any snapshot edit in this phase is a spec violation.

### TC-AB-003 — determinism (P0, integration)
**Steps:** `validate run --probes tests/fixtures/probe-set.yaml` twice, no
ingest between.
**Expected:** byte-identical reports (modulo the run timestamp field).

### TC-AB-004 — page-space scoring maps chunks correctly (P0, unit)
**Steps:** feed the scorer a chunk hit whose parent source page is in
`expected`.
**Expected:** credited as a hit for the chunk arm; a chunk from an
unrelated source scores zero.

### TC-AB-005 — frozen-set guard (P1, unit)
**Steps:** `validate run` against a probe file without `frozen: true`.
**Expected:** refuses with a message naming the freeze step; exit non-zero.

### TC-AB-006 — harvest produces candidates, repo untouched (P1, integration)
**Preconditions:** at least one ask trace exists (stub ask in the walk).
**Steps:** `validate harvest --out <tmpdir>`.
**Expected:** `candidates-<date>.yaml` with the real question text; `git
status` clean.

### TC-AB-007 — methodology header present (P1, unit)
**Steps:** generate any report.
**Expected:** the three pre-registered decisions appear in text and JSON.

### TC-AB-008 — empty/edge probes (P2, unit)
**Steps:** probe set with zero entries; probe whose `expected` slugs do not
exist.
**Expected:** zero-entry set refuses cleanly; unknown slugs score 0 and are
flagged in the report, not crashed on.

## Out of scope for Phase 1 (do NOT build)

- Milestone replays and the compounding curve — Phase 2.
- LLM-as-judge answer comparison — Phase 3, conditional, never pre-built.
- Exposing the chunk arm on `query`, the facade, or any surface.
- Snapshot restore tooling inside the runner — `backup` is the freeze.
- The pre-registered verdict *document* (§ 8) — the curator writes it before
  the first real run; this phase only prints what it needs to be read against.

## Open questions to confirm before starting

1. **Verb naming.** `compendium validate harvest|run` (recommended: fences
   the pathway and leaves room for Phase 2's `validate milestones`) vs
   `probe`/`ab` verbs.
2. **Probe judgment source.** `expected` slugs hand-labelled by the curator
   at freeze time (recommended — the probe set is small by design) vs
   seeded from the pages the original ask actually cited (risks circularity:
   the page arm graded by its own citations).
3. **Metrics set.** hit@K / recall@K / MRR at K=top_k (7) (recommended,
   mirrors the golden metrics) — anything else worth capturing per probe?
