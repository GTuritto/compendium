## Goal

Give the colocated agent verbatim, agent-owned object storage in PostgreSQL with
a one-way promote path into synthesis, without making the store a second system
of record or disturbing page-first retrieval.

## Why this plan exists

It locks in that the store is operational data (not the wiki, not a derived
index), that it is invisible to retrieval until promoted (ADR-001/003 hold),
that promote stops at the source layer (curator-driven synthesis holds), and that
it stays single-namespace/no-auth (the deferred bundle is not spent here).

## Out of scope (do NOT build)

- Per-agent namespacing / auth (deferred bundle; `collection` stays uncontrolled).
- Promote creating concepts or edges (stops at source; synthesis is curator-driven).
- Indexing the raw store into the derived stores (invisible until promoted).
- Agent-assigned tags here (pairs with tagging item, but agent-write deferred).

## Open questions to confirm before starting

1. Versioning: last-write-wins only, or an append-only history per key?
   Recommendation: LWW first; add history only if a use case appears.
2. Binary vs text-only at first. Recommendation: BYTEA from the start (text is
   the common case but binary costs nothing extra).
3. `object_list` bodies: metadata-only by default with opt-in bodies?
   Recommendation: metadata-only default.
