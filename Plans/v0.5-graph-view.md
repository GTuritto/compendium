## Goal

Add a read-only, Obsidian-style force-directed graph view to the WebUI over the
existing Memgraph knowledge graph, with filtering and click-through to pages.

## Why this plan exists

It locks in that the view is read-only (fits the WebUI safe-only posture), that
it reads through a bounded export rather than dumping the whole graph, and that
the renderer choice is a deliberate, stack-discipline-weighed dependency.
Without it, a graph view risks an unbounded render that does not scale and an
ad-hoc dependency.

## Testing plan

| # | Layer | Scenario | Verify |
| --- | --- | --- | --- |
| 1 | unit/integration | neighbourhood export | returns scoped nodes/edges within the limit; graph unchanged |
| 2 | integration | full-graph export on a large graph | capped, not unbounded |
| 3 | web | render + filter | only filtered nodes/edges render |
| 4 | web | node click | opens the page |
| 5 | web (contract) | read-only | no mutation possible from the view |

| --- | --- | --- | --- |
| v0.5-graph.1 | render | open the WebUI graph view for a concept | the concept + neighbours render |
| v0.5-graph.2 | click-through | click a neighbour node | its page opens |

## Out of scope (do NOT build)

- Graph editing from the view (read-only; structural edits stay curator/CLI).
- A TUI graphical render (the TUI keeps its text graph browser).
- Unbounded full-graph rendering (always capped/sampled).

## Open questions to confirm before starting

1. Renderer: pyvis vs streamlit-agraph vs d3. Recommendation: streamlit-agraph
   if it embeds cleanly, else pyvis HTML embed — least custom JS.
2. Full-graph node cap default. Recommendation: a few hundred nodes, with
   neighbourhood-of-a-page as the default entry.

golden); smoke section passing; dependency justified; version bumped; PR
