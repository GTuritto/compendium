# v0.6 — Interactive 3D knowledge-galaxy (WebUI): Implementation Plan

Date: 2026-06-16
Branch: `v0.6-galaxy-graph` (off `main`)
OpenSpec change: `openspec/changes/v0.6-galaxy-graph/`
Spec source: this change; ADR-023 (extends ADR-021). Approved spike:
`/tmp/compendium-debug/galaxy.html` (synthetic data, user-approved aesthetic).

## Goal

Add an interactive 3D knowledge-galaxy to the WebUI Graph view: nodes drift in
3D, cluster by subject, and connect by **semantic similarity** (Qdrant kNN),
rendered with vendored `3d-force-graph` (three.js) — read-only, no pip
dependency. Inspired by agentic-patterns.com/graph.

## Why this plan exists

It locks in: (1) the galaxy reads through a **bounded similarity export**, not a
dump; (2) the renderer is **vendored, no pip dependency, offline-capable**;
(3) the view stays **read-only** (WebUI safe-only posture); (4) graphviz stays
the **no-JS fallback**; and (5) click-to-open-page is explicitly **deferred**
(the one-way `st.components.v1.html` embed cannot return click events without a
bidirectional component build). Without it, the feature risks an unbounded
render, a runtime CDN dependency, or scope creep into a custom component build.

## Sub-phases

### Na — semantic-similarity export

**Purpose:** a bounded, read-only `{nodes, links}` payload from Qdrant kNN.

**Tasks:**

1. A new export (e.g. `compendium/graph/semantic_export.py`) that, for each page
   in scope (a focus page's neighbours by default; a bounded full-graph sample),
   pulls top-K neighbours via `nearest_neighbours()`, emits undirected
   similarity-weighted edges at/above a threshold, dedupes pairs, and caps nodes.
2. Hermetic tests with a stub Qdrant client; ADR-023 inline in
   `docs/Compendium.md`.

**Files added:** `compendium/graph/semantic_export.py`, tests
**Decision flagged:** edges are similarity-only (not Memgraph typed edges); node
cap + top-K + threshold defaults (open question 3).

### Nb — renderer + vendored asset

**Purpose:** the renderer, with no pip dependency and no runtime CDN.

**Tasks:**

1. Vendor minified `3d-force-graph` (+ three.js if not bundled) under
   `compendium/web/static/`.
2. A pure builder (`compendium/web/galaxy.py`) — payload in, embeddable HTML
   out, no I/O / no Streamlit — analogous to `graphviz.py`; hermetic test.

**Files added:** `compendium/web/galaxy.py`, `compendium/web/static/*.js`, tests
**Decision flagged:** vendored vs CDN (open question 1) — recommend vendored.

### Nc — WebUI galaxy mode

**Purpose:** the interactive view.

**Tasks:**

1. A 2D-graphviz | 3D-galaxy toggle in the Graph view; `st.components.v1.html`
   render of the builder output; controls for similarity threshold, top-K, node
   cap, node kind; node colour by kind, size by degree, edge width by weight.
2. Graphviz stays the no-JS fallback; headless builder test.

**Files modified:** `compendium/web/app.py`
**Decision flagged:** mode-toggle vs new view (open question 2); click-to-open
deferred — navigation stays via the focus selectbox.

### Nd — docs + close

**Tasks:**

   version bump.

**Files modified:** `docs/operations/graph-view.md`, `CHANGELOG.md`,

## Out of scope (do NOT build)

- Click-a-node-to-open-the-page (needs a bidirectional component build) —
  navigation stays via the focus selectbox; noted follow-up.
- A pip-installed graph component (streamlit-agraph etc.) — vendored JS only.
- Explicit-edge / shared-tag galaxy modes (this phase is semantic-similarity
  only; other modes are a later add).
- A TUI 3D render (the TUI keeps its text graph browser).
- Unbounded full-graph rendering (always capped/sampled).

## Open questions to confirm before starting

1. **Vendored vs CDN** for `3d-force-graph`. Recommendation: **vendored** under
   `compendium/web/static/` — the loopback WebUI should work offline and carry
   no runtime CDN dependency.
2. **Mode toggle vs new view.** Recommendation: a **2D | 3D toggle inside the
   existing Graph view**, keeping graphviz as the fallback (one view, two
   renderers) rather than a separate "Galaxy" view.
3. **Defaults:** top-K neighbours, similarity threshold, node cap.
   Recommendation: top-K ~8, threshold ~0.6, node cap 300 (reuse the ADR-021
   cap), all adjustable in the UI.
