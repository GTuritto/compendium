# v0.2 Phase 8 — Autonomous semantic-edge extraction: Implementation Plan

Date: 2026-06-01
Branch: `v0.2-phase-8-extract` (off `main`)
OpenSpec change: `openspec/changes/v0.2-phase-8-extract/`
Spec source: [docs/COMPENDIUM_V0.2_BUILD.md](../docs/COMPENDIUM_V0.2_BUILD.md) § Phase 8;
[docs/Compendium.md](../docs/Compendium.md) ADR-010.

## Goal

The slow loop autonomously proposes and writes `RELATED_TO` and `PREREQUISITE_FOR` edges into
Memgraph with provenance; the fast-loop expansion benefits without curator effort.
**Ships ADR-010.** This is the last v0.2 phase.

## Why this plan exists

ADR-009 made all semantic edges curator-driven, which keeps the graph thin and under-fires
the fast-loop expansion. ADR-010 selectively reverses the v0.1 "Not automated semantic-edge
extraction" line for the two edge types where the LLM is trustworthy, with honest provenance
so the decision stays reversible and auditable. This plan locks the shape so the autonomy
is narrow, bounded in cost, and never overwrites human work.

Three deliverables:

1. **A `from_extracted_edges` generator** in `compendium/curate/` (new `extract.py`), invoked
   by `compendium curate run` after the four ADR-009 generators, graph-backed and
   skip-graceful.
2. **kNN + one-call-per-page labelling.** For each changed page (+ periodic full sweep): top
   K=10 Qdrant neighbours, drop structural collisions, one LLM call labelling each pair
   `RELATED_TO` / `PREREQUISITE_FOR` / `NONE` + confidence.
3. **Provenance-aware writes.** Above-threshold (≥0.7) non-`NONE` labels become Memgraph edges
   carrying `extracted_by="llm"`, `model`, `confidence`, `extracted_at`, `source_revision_id`,
   `weight`; curator edges are never overwritten; LLM edges refresh; every proposal is logged.

The plan locks these decisions (also in the OpenSpec `design.md`):

1. **Generator inside the slow loop**, not a new CLI verb (ADR-010's home; the daemon already
   runs it).
2. **No migration** — provenance lives on Memgraph edges; the change-detection watermark is
   `max(extracted_at)` over LLM edges in the graph.
3. **One LLM call per source page** labelling all K neighbours (cost scales with turnover, not
   corpus size).
4. **Structural-collision pre-filter** (`PART_OF`/`EVIDENCES`/`GROUNDS`) before the call.
5. **Curator edges protected**; LLM edges refreshed; `weight = confidence` (curator stays 1.0).
6. **Source-page set = the Qdrant `pages` collection** (concept + source pages).

## Sub-phases

### 8a — Extraction primitives (graph + kNN)

**Purpose:** the graph and Qdrant building blocks the generator composes.

**Tasks:**

1. `compendium/graph/schema.py` / `browse.py`: `structural_pairs(driver, label, node_id)` —
   nodes already connected by `PART_OF`/`EVIDENCES`/`GROUNDS` (either direction).
2. `upsert_extracted_edge(driver, edge_type, a_label, a_id, b_label, b_id, props)` — `MERGE`;
   protect `extracted_by="curator"` (report `collision`); else set/refresh the full LLM
   provenance set (`written`/`refreshed`).
3. `max_llm_extracted_at(driver)` — the change-detection watermark; `None` when no LLM edges.
4. Extract the node-resolution rule (`source`→`:Source`/`source_id`; `concept`/`topic`→page
   id) into a helper shared with `links.py`.
5. `compendium/curate/extract.py`: `nearest_neighbours(qclient, page_entity_id, k)` over the
   Qdrant `pages` collection (fetch the page vector, query top `k+1`, drop self).
6. Unit tests: upsert create/refresh/curator-protect; `structural_pairs`; `max_llm_extracted_at`.

**Files added:** `compendium/curate/extract.py` (kNN portion)
**Files modified:** `compendium/graph/schema.py` (+ `browse.py`), `compendium/graph/links.py`
(share the resolution helper), `tests/test_graph.py` / `tests/test_curation.py`

**Decision flagged:** no migration; the watermark is graph-derived.

### 8b — The LLM labeller

**Purpose:** one prompt per source page → labels + confidence.

**Tasks:**

1. `compendium/curate/extract.py`: an `Extractor` protocol —
   `label(source, neighbours) -> list[Label]` (`{neighbour_id, label, confidence, direction}`).
2. `StubExtractor` (deterministic, hermetic tier).
3. `LLMExtractor` — one OpenAI-compatible call per page over `SYNTHESIS_*`; prompt `extract-v1`
   presents the source page + numbered neighbours, asks for a JSON array; parse defensively.
4. `get_extractor()` gated by `COMPENDIUM_SYNTH_STUB` (mirrors `answer.get_answerer`).
5. Unit tests: prompt numbering; JSON parsed into `Label`s; malformed dropped (not raised);
   `NONE` filtered.

**Files modified:** `compendium/curate/extract.py`, `tests/test_curation.py`

**Decision flagged:** one call per page; stub for the hermetic tier.

### 8c — The `from_extracted_edges` generator + curate wiring

**Purpose:** the end-to-end pass, wired into `compendium curate run`.

**Tasks:**

1. `config/settings.yaml` + `compendium/config.py`: a `curation.extract` block (`enabled`,
   `min_confidence: 0.7`, `top_k_neighbours: 10`, `full_sweep_every: 24`).
2. `compendium/curate/extract.py`: `from_extracted_edges(conn, driver, qclient, cfg)` —
   changed pages (revision newer than the watermark) or all pages on a full sweep; per source
   page: kNN → drop structural collisions → one `label()` → drop `< min_confidence` and
   `NONE` → `upsert_extracted_edge` with provenance (`weight = confidence`,
   `source_revision_id` = current revision). structlog per proposal.
3. `compendium/curate/run.py`: invoke after the ADR-009 generators inside `graph_connection()`,
   skip-graceful; fold counts into `CurateReport`
   (`extracted_edges: {written, refreshed, dropped_confidence, dropped_collision}`) + the run
   summary.
4. Full-sweep cadence: cold start or every `full_sweep_every` runs; else incremental.
5. Integration test (seeded corpus + stores + stub extractor): a run writes
   `extracted_by="llm"` edges with provenance; a curator edge on a labelled pair is untouched;
   a structural pair is pre-filtered; `graph status` shows the counts; a query trace's
   `graph_expansion` reaches a page via a new LLM edge.

**Files modified:** `config/settings.yaml`, `compendium/config.py`,
`compendium/curate/extract.py`, `compendium/curate/run.py`, `tests/test_curation.py`

**Decision flagged:** the generator is skip-graceful and idempotent across runs.

## Out of scope for Phase 8 (do NOT build)

- Autonomous `SYNTHESIZES` (lifecycle-owned via the promote hook) — forever.
- Autonomous `CONTRADICTS` (curator-only; v0.3+ Shape B "LLM suggests, curator approves").
- A `compendium extract` CLI verb (runs inside `curate run`).
- Retrieval re-ranking / filtering by `extracted_by` or `confidence` (expansion walks as-is).
- A PostgreSQL `edge_extraction_state` migration (watermark is graph-derived).
- The `compendium serve` service unit (ADR-012 later refactor; tracked separately).

## Open questions to confirm before starting

1. **Change-detection watermark.** Recommendation: derive from the graph (`max(extracted_at)`
   over LLM edges) — no migration. Alternative: a small `edge_extraction_state` table.
2. **Full-sweep cadence.** Recommendation: cold start + every `full_sweep_every` runs
   (default 24). Alternative: time-based (weekly).
3. **`weight` of LLM edges.** Recommendation: `weight = confidence` (curator stays `1.0`).
4. **Source-page set.** Recommendation: concept + source pages (the Qdrant `pages` collection).
5. **Labeller module + prompt id.** Recommendation: `compendium/curate/extract.py` + an
   `Extractor` seam, prompt id `extract-v1`.
6. **Report shape.** Recommendation: add
   `extracted_edges: {written, refreshed, dropped_confidence, dropped_collision}` to
   `CurateReport` and the run summary.
