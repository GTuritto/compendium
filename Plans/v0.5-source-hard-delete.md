## Goal

Give Compendium a hard delete for an ingested source: remove the source and
everything derived from it (chunks, the source page + its vault file, the
derived-index entries, the graph nodes) so it leaves retrieval entirely,
closing the one-way ingest door without disturbing the curated-wiki invariants.

## Why this plan exists

It locks in the delete semantics (hard purge, source-scoped), the
canonical-first ordering and the self-reconcile guarantee, the decision to
surface dangling concepts via curation rather than cascade-deleting them, and
the decision to keep delete off the no-auth network surface. Without it, the
corpus only grows, and a mis-ingest permanently contaminates both retrieval and
the v0.4 measurement.

## Sub-phases

### Na — delete orchestration

**Purpose:** one correct, idempotent `delete_source` over the existing primitives.

**Tasks:**

1. Add `delete_source(conn, source_id)` to `repository.py`: resolve the source
   page; delete the vault markdown file and the `wiki_pages` row; delete the
   `sources` row (cascades `source_documents` + `chunks`); delete
   `semantic_edges` referencing the source/its chunks; delete the OpenSearch
   docs and Qdrant points for the page + chunks; remove the Memgraph
   Source/Chunk nodes and edges; clear `index_sync_state` rows.
2. PostgreSQL work in one transaction; derived-index deletes after commit,
   best-effort, with the reconcile guarantee documented.
3. Tests: full purge, idempotent re-run, re-ingest-after-delete is clean,
   partial-derived-failure then `reindex`/`graph rebuild` reconciles.

**Files added:** `tests/test_delete.py`
**Files modified:** `compendium/db/repository.py`

**Decision flagged:** canonical-first ordering; derived deletes are best-effort
and reconcilable (ADR-001), not part of the PG transaction.

### Nb — CLI verb

**Purpose:** the operator entry point.

**Tasks:**

1. `compendium source delete <id|slug> [--dry-run] [--force]` in `__main__.py`.
2. `--dry-run` prints the impact summary (chunk/page/index counts, concepts
   left thinly grounded); the destructive path confirms.

**Files modified:** `compendium/__main__.py`

**Decision flagged:** destructive, so CLI/TUI only — never on the facade.

### Nc — TUI action

**Purpose:** delete from the sources screen.

**Tasks:**

1. A delete action behind an explicit confirmation, reusing the orchestration.
2. Headless Pilot test.

**Files modified:** the TUI sources screen module.

**Decision flagged:** none.

### Nd — dangling-concept signal

**Purpose:** make the curated fallout visible.

**Tasks:**

**Files added:** `docs/operations/delete.md`

## Testing plan

| # | Layer | Scenario | Verify |
| --- | --- | --- | --- |
| 1 | integration | `delete_source` on an ingested source | no rows/vault file/index entries/graph nodes remain |
| 2 | integration | re-ingest the same file after delete | ingests as a fresh source |
| 3 | integration | derived-delete failure injected | canonical gone; `reindex`+`graph rebuild` reconciles |
| 4 | integration | delete a sole-grounding source | concept survives; `curate run` surfaces a dangling signal |
| 5 | unit | `source delete --dry-run` | impact summary printed; corpus unchanged |
| 6 | tui | sources-screen delete with confirm | source removed; list refreshes |
| 7 | contract | access surface inspected | no delete verb on HTTP/MCP |

## Out of scope (do NOT build)

- Deleting concept/topic pages (a curation decision; backlog item 3/4, ADR-020).
- A full knowledge-base wipe (admin-surface backlog item 3).
- Any delete verb on the facade / HTTP / MCP (destructive stays CLI/TUI).
- Tombstones / a deletions audit log (the chosen semantics are hard delete).

## Open questions to confirm before starting

1. Refuse to delete a source that is the **sole** grounding of a *canonical*
   concept unless `--force`? Recommendation: yes — refuse with a clear message
   listing the affected concepts; `--force` overrides. Safer default.
2. Slug vs id as the primary CLI argument? Recommendation: accept either,
   resolve slug to id.
