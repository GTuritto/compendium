## 1 · One chat-completion envelope behind the model-client seam — Strong

**Files:** `answer/llm.py` · `wiki/synth.py` · `curate/extract.py` · `model_clients.py`

**Problem.** `OpenAI(base_url=endpoint, api_key=api_key or "not-needed")` is
byte-identical at `llm.py:90`, `synth.py:59`, `extract.py:183`; the
create-then-parse envelope repeats five times (rewrite, buffered compose,
streaming compose, synthesize, label). Token accounting (`Completion` +
`_approx_tokens`, `llm.py:25-36`) exists only in the answerer — `profile stats`
now makes the asymmetry visible: it prices one of the three paid LLM paths.

**Solution.** One deep `chat(... , on_token=None) → Completion` beside the
model-client registry owns construction, the create call, the streaming loop,
and the usage fallback. Protocols, stubs, prompts, and parsers stay put; PR #54's
registry keeps owning stub-or-real selection.

**Wins:** locality (envelope/usage rules once) · leverage (one interface, five
call sites) · synth + extract gain token accounting free · streaming tested once
· deletion test: copies reappear 5×.

## 2 · Route the status readers through the probe() seam — Strong

**Files:** `service_unit/__init__.py` · `schedule/status.py` · `api/service.py`

**Problem.** `service_unit.probe()` (`__init__.py:86-94`) exists precisely for
status readers — injectable `Runner`, raw scheduler-CLI output — and has zero
callers beyond `inbox/install.py:105`. Both readers re-implement platform
dispatch and run the identical `launchctl print` command themselves
(`status.py:85-86`, `service.py:139`); neither is testable without
monkeypatching `subprocess`.

**Solution.** Both readers consume `Probe`; field-extraction regexes stay
per-service (the seam's documented intent). On Linux the seam grows the richer
activity probe the schedule reader needs; on macOS it is a drop-in.

**Wins:** deletes duplicated platform dispatch ×2 · readers become pure parsers
over recorded CLI output (the interface is the test surface) · locality for
launchctl quirks · reverse deletion test: the bypassed probing deletes with no
complexity reappearing.

## 3 · Name the index-document shape once — Worth exploring

**Files:** `index/documents.py` · `index/opensearch.py` · `retrieve/search.py` · `retrieve/pipeline.py`

**Problem.** The page/chunk document shape exists only as matching string keys
in four places: the builders (`documents.py:42-111`), the OpenSearch mappings
(`opensearch.py:60-105`), the searchable-field lists (`search.py:28-29`), and
the `.get()`-with-silent-default consumers (`pipeline.py:93-115`). The per-store
difference leaks: `_chunk_citation` knows OpenSearch carries `body` while Qdrant
carries `body_preview` (`pipeline.py:108`). A renamed field degrades to empty
strings with no failing test.

**Solution.** Declare the shape once in `documents.py` (typed record per entity
kind) with `to_opensearch()`/`to_qdrant_payload()` adapters and a typed hit
reader. Wire format stays byte-identical; StoreProjector and RRF untouched.

**Wins:** field drift fails at construction · locality for shape evolution ·
the body/body_preview split stops leaking · highest AI-navigability win.

## 4 · Finish the facade: input coercion and error modes live once — Worth exploring

**Files:** `api/facade.py` · `api/http.py` · `api/mcp.py`

**Problem.** The facade's docstring promises the transports "cannot drift", yet
the ingest decision tree (base64 decode, path-vs-bytes, reject neither) is
duplicated at `http.py:69-94` and `mcp.py:73-94`, and drift is already real: a
missing page is HTTP 404 (`http.py:101`) vs MCP JSON `null` (`mcp.py:97-98`).

**Solution.** `facade.ingest` accepts the surface's actual input shape
(`content_base64` + `filename` alongside `path`) and owns decoding, validation,
and one error message; the facade documents one not-found convention that both
transports render natively. The six-verb set (ADR-011), `to_payload`, and the
transport-native streaming bridges stay put.

**Wins:** error modes join the one interface · facade tests cover both
transports · deletes the duplicated tree · third adapter (MCP-SSE / LAN HTTP)
is already on the v0.3 roadmap.

## Assessed and recorded — no seam (stop re-suggesting)

- **Off-queue graph rebuild** — benign post-ADR-013 (semantic edges replay from
  PostgreSQL; a failed rebuild is rerunnable). Closes review #2's open item.
- **Per-entity query DSL in `retrieve/search.py`** — fails the deletion test;
  the deprecated-page filter is a semantic difference.
- **Reachability-check dedup** — the abstraction would outweigh the duplication.
- **Import-time caching of `COMPENDIUM_PROFILE`** — the per-call env read is
  load-bearing (`--profile` sets the variable in `main()`, after imports).
- **Timed-span stage names as free strings** — an enum is a pass-through
  wrapper; the stats SQL aggregates whatever keys exist.
- **CI service-container blocks copied per job** — mandated by GitHub Actions
  (no YAML anchors, no job-level service reuse).
- **CLI dispatch if-chain (21 branches)** — each branch is one tail call into a
  parse → call → render handler; a verb registry adds no leverage.
- **The ten profile-stats repository readers** — deliberately thin per the
  ADR-004 raw-SQL rule, like the rest of `repository.py` (review #1).

## Top recommendation

**Candidate 1 first** — highest leverage (five envelope copies, three modules),
and closing the token-accounting asymmetry feeds real numbers into
`profile stats`. Then candidate 2, which is mostly deletion. Candidates 3 and 4
follow as the Worth-exploring pair; 3 carries the larger blast radius and is
golden-gated.
